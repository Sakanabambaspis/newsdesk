# Wayfinder map: workflow-modules

A wayfinder map (local-markdown tracker; tickets in `issues/`, frontier =
open + unblocked + unclaimed, first by number). Work it with `/wayfinder`.

## Destination

The workflow-module architecture shipped on main: data-defined versioned
workflows run by a guardrail engine with bounded loop checks (W1), a
retrievable variant catalog (W2), rubric-scored selection strategies (W3),
multi-Station publishing with per-station feeds (W4), and MCP tools for
chat-driven customization (W5) — with W6 (elicitation playbook) scoped, ship
or defer. Done means every milestone ticket's measurable acceptance is green.

- Conventions: ADR/posture rules in `docs/DESIGN.md`; config knobs env-wired, documented, test-pinned (config-audit 2026-09-17); every mutation actor-tagged in the log.

## Decisions so far

- [Workflow-module architecture (founding record)](../../docs/proposals/workflow-architecture-20260919.md) — 7 modules, linear stage-list interpreter over plugin registries, W1–W6 milestones, Station naming, MCP-first chat surface, rubric-as-data.
- [CI topology for multi-station runs](issues/11-ci-station-topology.md) — one scheduled workflow, matrix over station ids with `fail-fast: false` and no `continue-on-error` (isolation without killing the failure email), `morning` concurrency and 45-min per-leg timeout unchanged; per-station workflow files only if schedules diverge (`docs/research/gha-station-topology.md`).
- [Descriptor schema v1](issues/01-descriptor-schema.md) — six-stage vocabulary approved (digest→select, script→compose, tts→render); per-type Cordis triples with validator-enforced chain coherence; closed named-check set with strict per-name params and `on_fail` repair(≤2, schema-bounded)/fail; descriptor self-describes as `name`+`version`; `default-morning@1` shipped unpinned with only behavior-true checks (section_allowlist, word_budget, archive_intact) — cluster/diversity checks land with W3. Code: `newsdesk/workflow/schema.py` + `descriptors/default-morning@1.json`.
- [Engine & RunContext contract](issues/02-engine-run-context-contract.md) — `run_workflow(session, settings, descriptor, station=None, *, date, dry_run)` → today's plain report dict; **stage keys are stage names** (`default-morning@1` names renamed stages with today's keys digest/script/tts); RunContext is the one channel (bus by triple keys, repair bookkeeping, log; invariant "artifact-visible means bus-keyed" recorded on `workflow_stage_finished`); dispatch per type (collect/select built-ins; registry pins else settings knobs; notify fan-out) with pre-flight "selection" tagging; checks phase-bound per name (pre: archive_intact; post: the rest), repair ≤2 → contained degrade → loud; uniform `workflow_stage_*`/`workflow_run_*` events supersede `morning_run_*` at ticket 05; guard-before-first-stage; dry-run stops before publish. Behavior preservation pinned twin-world vs `run_morning`. Code: `newsdesk/workflow/engine.py` + `tests/test_workflow_engine.py`.
- [Characterization harness for the default chain](issues/03-characterization-harness.md) — `tests/test_characterization_default_chain.py` pins the chain's absolute observable outputs offline (digest shape incl. flattened material-pack stats, extractive + stubbed-LLM sidecars verbatim, audio report + chunk manifest, publish report in both host modes + manifest, full-run stage payloads + exact 12-entry log sequence); acceptance proven with bogus LLM/token env set and by mutation-checking red-capability. Absolute pins (independent of the twin-world comparison in ticket 02) mean any stage behavior change flips red during the W1 rewrite.
- [Catalog versioning semantics](issues/04-catalog-versioning-semantics.md) — identity `name@version`, integer versions dense (next = max+1) and never reused; `latest` computed, never stored (no pointer row); `name`/`name@latest` float at run start, `name@N` pins, and every engine event already records the version that ran, so reproducibility lives in the log; `workflow_versions` INSERT-only (no update/delete methods; a bad version is superseded, gaps refused); every mutation takes a *required* actor (`system|user|agent`) and logs `workflow_*` actions with `via` origin; retire is a name-level `retired_at` flag (un-retire logged; delete not expressible; per-version quarantine deliberately not in v1); retired names refuse new versions/bindings/runs and existing bindings fail loudly at pre-flight (`selection`) — never silent-skip or silent-fallback; diff = structural JSON ({path (RFC 6901), kind: added|removed|changed|order, before, after}) with stages keyed by name and reorders as one `/stages` order change; seed v2 `format: 2` carries full descriptor documents (no indirection within workflows; stations reference workflows by ref string in ticket 12), import idempotent on (name, version) with parsed-equality conflict → loud `SeedError`, retirement round-trips monotonically (never un-retires), export = full history; validation on save AND on load (the DB is a boundary channel newsdesk doesn't exclusively control — load-time checks are boundary checks, not consumer checks); shipped `default-morning@1` bootstraps the catalog idempotently then freezes; the engine stays catalog-blind — enforcement at `resolve(ref)` in `newsdesk/workflow/catalog.py` (built by ticket 06).
- [W1 built: morning routes through the engine](issues/05-implement-w1-schema-engine.md) — `newsdesk morning` = shipped `default-morning@1` → `run_workflow` (catalog-blind until ticket 06); `run_morning` kept as the characterization specimen (suite untouched and green; the workflow/→morning import flip is superseded until W2 retires it — the one new opposite edge is `morning.registries → workflow.schema`, no cycle, `workflow/__init__` stays import-light); the 2026-09-19 checks attach to **compose** (post) with a provisional spec (story = normalized headline, theme = matched watchlist terms, floors scale to what the pack offered — quiet days never fail; formal spec at ticket 08): a syndication cluster filling the slots or single-theme coverage now fails loudly after bounded repairs + contained degrade, nothing published; `duration_band` implemented but unattached (a policy number for a v2); registration metadata wired (validated triple, closed params key sets enforced at pre-flight, `context=True` plugins — `llm-brief` skips its LLM call on the degrade pass); `validate_registration` moved to schema.py (engine re-exports); `pack[0:4]` untouched — W3 replaces selection. Code: engine check library + registry metadata + `tests/test_workflow_coverage_checks.py` (the two repro loops).
- [W2 built: catalog + seed v2 + CLI](issues/06-implement-w2-catalog-seed-cli.md) — ticket-04 semantics built and pinned: `WorkflowCatalog` in `workflow/catalog.py` (create_version dense/never-reused with required actor, computed-latest `resolve()` as the only run path, `document()` inspection that retirement doesn't refuse, versions/list/retire/unretire/diff, validate-on-load everywhere, private document copies), tables in `core/models.py` (contract pin 7→9); `diff_descriptors` keyed by stage name with one `/stages` order entry on **any** sequence change (position is behavior); seed v2 (`format: 2` gate, full-document `workflows` + name-level `retired_workflows` section — retirement is monotonic, a seed never un-retires; full-history export; loud conflicts; required actor); CLI `newsdesk workflow create/get/list/history/diff/retire/unretire` (actor=user, via=cli; seed import actor=user, via=seed); `newsdesk morning` now bootstraps the shipped `default-morning@1` (actor=system, via=shipped, once) and floats `resolve("default-morning")` — retired default fails the run loudly; committed seed file mechanically bumped to format 2 for CI (production re-export stays ticket 12). Code: `newsdesk/workflow/catalog.py` + `tests/test_workflow_catalog.py` + `tests/test_seed.py`.
- [Rubric schema + scorer contract](issues/07-rubric-schema-scorer.md) — the rubric is pure data (`format_version: 1`, `name@version`, `dimensions[]{name, description, weight>0, proxy?, anchors?}`, `thresholds{min_score}`) that chat vocabulary compiles into; the one scorer `score_items(rubric, items, adapter, *, window_hours, now)` returns per-item newsdesk-computed totals (weighted mean over *scored* dimensions; the model never emits totals) plus **per-dimension** stored reasons (ADR 0001 strengthened from per-item); dimensions with a `proxy` (`relevance` | `recency` | `corroboration`, closed set) are computed mechanically in *every* path and the LLM scores only the rest — an all-proxied rubric needs no model; the no-key fallback is the same formula minus the model, all-or-nothing (model and mechanical fills never mix), unproxied dimensions excluded-and-renormalized (`unassessed`, not zeros), cause visible in `llm_error`; with the shipped `default@1` the formula is exactly recency + watchlist relevance + corroboration; attachment is by ref string (float `default` / pin `default@N` per ticket 04, resolved at run start, loud pre-flight failure on missing/retired — never silent fallback) and rubrics are catalog-versioned with ticket-04 semantics (storage mechanics ticket 09); scores/reasons are run outputs riding the select report and log, never catalog state; `story_key` unified in `rubric.py` (engine delegates; ticket 08 owns the formal spec); `min_score` is selection policy consumed by the strategies (ticket 08). Code: `newsdesk/workflow/rubric.py` + `rubrics/default@1.json` + `BaseLLMAdapter.score_rubric` + `tests/test_workflow_rubric.py`.
- [Strategies + repair policy](issues/08-strategies-repair-policy.md) — selection is one common pipeline (window → 30-cap → verdict filter → rubric scoring of **all** candidates → `min_score` admission → strategy pick → pack in final episode order; scoring precedes collapse so the corroboration signal counts publishers across the candidate set; writer contract untouched: deep=`pack[0]`, heads=`pack[1:4]`); story = `story_key`, the normalized headline, whole v1 spec (different headlines are different stories; empty-key items excluded from story counts); cluster collapse at pick time, representative = best total (tie fresher, id), cluster size = distinct publishers on the card as `outlets`, spoken "covered by N outlets"; the three strategies ship as **separate registered plugins** pinned by `plugin` on the select stage — unpinned select stays the legacy built-in, so frozen `default-morning@1` keeps its pinned behavior — `top-k-interesting {rubric, k, hours?}` (interesting = rubric total), `trending-impactful-mix {rubric, k, hours?}` (trending = corroboration breadth = distinct publishers, impactful = rubric total; deep = best impactful, then floor(k/2) trending slots with cross-backfill), `single-deep-dive {rubric, hours?}` (one story or empty pack — never padded); rubric ref is a required param resolved at pre-flight (ticket 07 semantics; storage mechanics = 09); diversity floor formalized: theme = matched watchlist term, both coverage floors scale to the **admissible set** (post-filter, post-min_score candidates) — not the pack, which would let a single-theme pick lower its own floor — so the select artifact must expose the admissible set (09); checks stay post-compose (no closed-set check can bind at select → strategies never enter the repair loop; the coverage pair remains the defect backstop); repair numbers: `max_attempts` per-workflow 1..2 default 2 (worst case 4 invocations), `on_fail` per check (`archive_intact` fail, rest repair), degrade = contained extractive then loud, nothing published, notes = the current attempt's violation strings on `ctx.violations[stage]` — and the ticket-05 thread closes: **no plugin acts on notes in v1**, a fired coverage check is a defect (intrinsic collapse is the 2026-09-19 defense); availability-vs-floor is a per-version check edit, not plugin behavior.
- [W3 built: select strategies + rubric catalog](issues/09-implement-w3-select-strategies.md) — the common pipeline lives in `workflow/strategies.py` (`SELECT_STRATEGIES` registry beside the morning ones, no settings knob; one plugin per strategy, closed param key sets) reusing digest-extracted primitives (`candidate_items` — the 30-cap is absolute again, `classify_verdicts`/`technical_only` verbatim, `item_card` public); collapse groups the admissible set by `story_key`, representative = best total/fresher/id (story-level ties inherit the rep id), `outlets` = `publisher_counts` over the *scored* set — the same number the corroboration reason cites even when `min_score` evicts copies; mix = best-impactful → floor(k/2) trending → impact fills to k (two takes are the whole backfill — the pools rank one set); scores/reasons/rubric ref/method ride artifact + report + `select_scored` log; the rubric catalog is built (`workflow/rubric_catalog.py`, `rubrics`+`rubric_versions`, ticket-04 semantics, contract pin 9→11, shipped `default@1` bootstraps at first pinned-select pre-flight — legacy runs touch nothing, no rubric CLI/seed yet: surfaces are tickets 13/14); the engine resolves pinned select + its required `rubric` ref at pre-flight (`selection` tag, float/pin, loud on missing/retired/malformed; two different pins refused), the select artifact exposes `admissible` and **both coverage floors now measure it** (a small pick cannot lower its own floor — pinned: single-deep-dive under the default 2-theme floor fails loudly), and "strategies never enter the repair loop" is *enforced*: `_CHECK_REQUIRES` + pre-flight binding validation refuses any check bound before its provider stage (no doomed repair loops); bounded-repair on strategy workflows pinned (4 compose invocations → contained degrade → loud, nothing published); 2026-09-19 regression pinned (three syndicated copies leave exactly one in the episode); sanctioned pin flips: characterization digest gains `admissible` (= `items` keyless), coverage messages say "the admissible set offers N", table count 11; review follow-up (7381cf3): the writer now *speaks* the cluster breadth — strategy cards say "Covered by N outlets." with the phrase's words reserved inside the clip budget, legacy cards byte-identical.
- [Station model + publish topology](issues/10-station-model-publish-topology.md) — one invariant drives the design: GUIDs/enclosure URLs are permanent, so stations are added *around* the legacy feed, never by moving it. Station = `stations` row with catalog conventions (retire-never-delete, required actor, no credentials): `name` slug (CLI arg + GUID prefix; immutable once episodes exist), nullable `watchlist_id` (NULL = global term union; source scoping rides `watchlist_sources`, one watchlist per station — no station↔source table), `workflow_ref` float/pin per ticket 04, unique nullable `path_segment` (NULL = legacy root `<base>/<token>/…` for the default station; others `<base>/<token>/<segment>/…`; immutable), feed identity columns (NULL → `feed.py` constants so the seeded default reproduces today's feed byte-for-byte; mutable — metadata only), `retired_at` monotonic; no artwork column (v1 ships the generated PNG; fog). Topology: one Pages project, one shared `NEWSDESK_FEED_TOKEN`, per-station subpaths, per-station secrets none (`NEWSDESK_STATION` is the only per-station env) — and because a Pages deploy is the complete site, each station leg fetches back and stages the **union of all stations' archives** (archive-intact posture widened); local-dir writes only its own subtree. GUID `<station>-<date>` (default = today's `morning-briefing-<date>`); idempotency per (station, date) on that station's own manifest; station runs sidecar to `<morning_dir>/<station>/<date>/`, station-less keeps the pinned legacy layout. F1 lands as a ctx-supplied scope (terms + attached-source filter) threaded into `candidate_items`/`build_daily_digest` — strategies stay stations-table-blind, D7 retired for station runs only, legacy path byte-identical, F1's per-publisher cap deferred (fog). `--station` flag / `NEWSDESK_STATION` env; absent = station-less legacy run that never reads the stations table. Seed v2 gains `stations` (name-keyed, identity indirection, monotonic retirement, loud conflicts; ships `morning-briefing` with `path_segment: null`).
